# Gatekeeper API: production-readiness audit

Scope: `apps/api` (Express 5, TypeScript, Prisma 6.19.3, Postgres 16). Date: 2026-10-30. This was a read-only code review plus live probes against the docker stack on :4000.

## Summary

| Severity | Count |
|---|---|
| BLOCKER | 5 |
| HIGH | 6 |
| MEDIUM | 11 |
| LOW | 12 |

**What works.** Tenancy scoping and IDOR protection are consistently good. Every service query filters by `societyId`, and resident-scoped queries also filter by `flatId`. I probed 12 or more cross-flat and cross-society IDOR attempts live and every one returned 404 or 403 (see section 2). The other things done well:
- Membership status is re-checked on every request, so deactivation takes effect immediately.
- The OTP attempt counter is race-safe.
- `JWT_SECRET` has a minimum length of 32.
- Prisma and stack traces do not leak to clients.
- The body limit is 100kb.
- The `?token=` query string is stripped from request logs.
- Typecheck is clean and 57 of 57 tests pass.

**What doesn't.** The launch blockers are missing production integrations (SMS, payments, account deletion) and fail-open defaults. On security, the OTP rate limiter can be bypassed and anyone can look up the name behind any registered phone number.

## 1. Auth details
- **OTP generation.** `crypto.randomInt` produces 6 digits, hashed with bcrypt cost 10, TTL 5 min, max 5 attempts. The attempt is reserved atomically before compare (good, `auth.service.ts:27-31`). Consuming the code is a compare-and-set inside a transaction (good). A new request invalidates older codes.
- **When `devCode` is returned.** It is returned when `EXPOSE_DEV_OTP=true`, or when `EXPOSE_DEV_OTP` is unset and `NODE_ENV != production`. Unset `NODE_ENV` defaults to `development`, so the default is to **expose** it (B4). There is a guard that exits only when `NODE_ENV=production` **and** exposure is on (`config.ts:33-36`).
- **JWT.** `JWT_SECRET` is required with min length 32 and has no code default. However, there is a known default in `.env.example` and compose (H3). Tokens use HS256 with a 7-day lifetime, and there is no refresh, revocation or logout (H2).
- **Deactivated membership.** `requireMember` checks `status: 'ACTIVE'` on every request (`tenancy.ts:8`), and `hub.dropMembership` closes SSE streams, but only on the local instance. A token for a deactivated member therefore gets 403 for that society straight away, while user-scoped routes still work.

## 3. Validation, errors, HTTP hardening
- zod covers all bodies and queries (L7). The error handler returns no stack and no raw Prisma message (L4). helmet uses defaults. CORS is OK (L6). The body limit is `100kb` (`app.ts:44`); a 200 KB body got 413 live, and malformed JSON got 400.
- pino-http's `req` serializer logs only `id`, `method` and the path without the query, so the SSE `token` and the Authorization header are never logged. `redact` also lists `req.headers.authorization` and `*.token`. The heartbeat runs every 25 s (`config.ts:42`). There is no SSE connection cap (M1).

## 0. Conventions

| Topic | Rule |
|---|---|
| Naming | Prisma models/fields are camelCase. Physical tables/columns are snake_case via `@@map` / `@map` (e.g. `Visitor.checkInAt` → `visitors.check_in_at`). Postgres enum types are snake_case too (`VisitorStatus` → `visitor_status`). |
| Primary keys | `id String @id @default(cuid())` → `text` PK, generated by Prisma client (not the DB). |
| Timestamps | `createdAt` (`@default(now())`) on every table; `updatedAt` (`@updatedAt`, set by Prisma client) on every mutable table. All instants are `timestamptz(3)` stored in **UTC**; UI renders `Asia/Kolkata`. |
| Calendar dates | `Invoice.dueDate`, `Expense.spentOn` are `date` (no time component). Prisma returns them as `DateTime` at 00:00 UTC. |
| Money | `Int` (`integer`) **paise**. ₹1 = 100. ₹3,500.00 → `350000`. Max ≈ ₹2.1 crore per value. Never floats. |
| Phone | Digits only, 10–15 chars (`varchar(15)`), validated by Zod at the API. |
| Tenancy | Every society-owned row carries `societyId`; every society-scoped query filters by `req.member.societyId`. |
| Actors | `…ById` fields reference `Membership.id` (the actor *in that society*), never `User.id`. Exception: `Notification.userId` → `User.id`. |
| `NoAction` | `ON DELETE NO ACTION`: same effect as RESTRICT (delete is refused while referenced) but checked at end of statement, so a hard delete of a `Society` cascades cleanly in one statement. Verified against Postgres 16. |

**Type column legend:** `Prisma type / Postgres type`. **Null:** `N` = NOT NULL, `Y` = nullable.

### Fields added beyond the brief

| Model | Field / item | Why |
|---|---|---|
| `TicketComment` | `societyId` (FK → societies, Cascade) | Tenancy rule (society-owned row) and lets a Society hard-delete cascade comments before their author memberships (verified; without it the cascade fails). |
| `StaffFlat`, `PollOption`, `PollVote`, `TicketComment`, `Payment` | `createdAt` | Standard audit column (brief: "all have createdAt"). These rows are immutable so have no `updatedAt`. |
| `OtpCode`, `Notification`, `StaffAttendance`, `Expense` | `updatedAt` | Rows are mutable (attempts/consumedAt, readAt, checkOutAt, edits). |
| `Payment` | `createdAt` alongside `paidAt` | `paidAt` is business time (may be back-dated for CASH); `createdAt` is row-insert time. |
| Column sizes | `varchar(15)` phones, `char(6)` passcodes, `char(7)` period, `char(5)` HH:mm, `varchar(10)` pincode | Cheap DB-level guard on fixed-format strings. |
| Extra indexes | see §4 (rows marked *added*) | Support the list/filter endpoints in brief §7. |

## 3. Business rules

All transitions are enforced in the service layer (state-machine helpers). Any transition not listed → **422** `INVALID_TRANSITION`.

### 3.1 Visitor

| From | To | Trigger / actor | Side effects |
|---|---|---|---|
| — | PENDING_APPROVAL | Guard `POST /visitors` | `loggedById` = guard; emit `visitor.requested` to flat's ACTIVE residents |
| — | CHECKED_IN | Guard `POST /gate/verify` with valid pre-approval passcode | `preApprovalId`, `checkInAt` = now; PreApproval `usedCount++` |
| PENDING_APPROVAL | APPROVED | Resident of flat: APPROVE | `decidedById`, `decidedAt` |
| PENDING_APPROVAL | DENIED | Resident of flat: DENY | `decidedById`, `decidedAt` |
| PENDING_APPROVAL | LEFT_AT_GATE | Resident: LEAVE_AT_GATE (**type = DELIVERY only**) | `decidedById`, `decidedAt` |
| PENDING_APPROVAL | EXPIRED | System, `createdAt` + 10 min with no decision | — |
| APPROVED | CHECKED_IN | Guard check-in | `checkInAt` |
| CHECKED_IN | CHECKED_OUT | Guard check-out | `checkOutAt` |
| LEFT_AT_GATE | COLLECTED | Guard or resident `/collect` | — |

Terminal: DENIED, EXPIRED, CHECKED_OUT, COLLECTED. Every change emits `visitor.updated`.

### 3.2 Ticket

| From | To | Actor | Side effects |
|---|---|---|---|
| — | OPEN | Resident (or admin) | — |
| OPEN | IN_PROGRESS | Admin | optionally set `assignedToId` |
| OPEN / IN_PROGRESS | RESOLVED | Admin | `resolvedAt` = now |
| RESOLVED | IN_PROGRESS | Admin (reopen) | `resolvedAt` = null |
| RESOLVED | CLOSED | Admin or raiser | — |
| OPEN | CLOSED | Admin (invalid/duplicate) | — |

Terminal: CLOSED. Comments allowed in any non-CLOSED state.

### 3.3 PreApproval

| From | To | Trigger |
|---|---|---|
| — | ACTIVE | Resident creates; `validTo > validFrom`, `maxUses ≥ 1` |
| ACTIVE | USED | Gate verify makes `usedCount` = `maxUses` |
| ACTIVE | CANCELLED | Resident `DELETE /preapprovals/:id` (soft) |
| ACTIVE | EXPIRED | `now > validTo` (lazy on read/verify or sweeper) |

Gate verify accepts only `status = ACTIVE AND validFrom ≤ now ≤ validTo AND usedCount < maxUses`.

### 3.4 SosAlert

| From | To | Actor | Side effects |
|---|---|---|---|
| — | RAISED | Resident | emit `sos.raised` to on-duty guards & admins |
| RAISED | ACKNOWLEDGED | Guard/admin | `acknowledgedById`, `acknowledgedAt`; emit `sos.updated` |
| RAISED / ACKNOWLEDGED | RESOLVED | Guard/admin | `resolvedAt`; emit `sos.updated` |

### 3.5 Invoice

| From | To | Trigger |
|---|---|---|
| — | UNPAID | Admin `POST /invoices/generate` (one per flat per period; existing (flat, period) skipped → unique key) |
| UNPAID | OVERDUE | `today > dueDate` (Asia/Kolkata), lazy or scheduled |
| UNPAID / OVERDUE | PAID | `POST /invoices/:id/pay` creates a `Payment` with `amount = invoice.amount` in the same transaction |

Terminal: PAID. v1 has no partial payments; `Payment` is 1:N only to allow future part-payments/refunds.

### 3.6 Passcodes
- Exactly 6 digits (`^[0-9]{6}$`), stored as `char(6)` text (keeps leading zeros).
- **Staff:** unique per society — DB `UNIQUE (society_id, passcode)` on `staff`. Permanent until changed.
- **PreApproval:** unique among **ACTIVE** rows per society — **app-enforced** (Prisma cannot express a partial unique index). Generation loop: random code → reject if an ACTIVE pre-approval *or* any staff in the society has it → retry. Lookup uses index `(society_id, passcode)`. Optional hardening in a raw migration: `CREATE UNIQUE INDEX ... ON pre_approvals(society_id, passcode) WHERE status = 'ACTIVE'`.
- **Cross-type:** a staff passcode and an ACTIVE pre-approval passcode must never collide in the same society, because `POST /gate/verify` resolves both from one input.

### 3.7 Other rules
- **Money:** every amount is integer paise; API accepts/returns paise; UI formats ₹ with 2 decimals.
- **Time:** instants stored UTC (`timestamptz`); "today", periods, due dates and amenity hours are interpreted in `Asia/Kolkata`. `Amenity.openTime/closeTime` are local wall-clock "HH:mm".
- **Tenancy:** every society-owned table carries `society_id` (all except `users`, `otp_codes`, `societies`, and the pure child tables `staff_flats`, `poll_options`, `poll_votes`, which inherit scope through their parent). Services always filter by `req.member.societyId` and must check that referenced ids (flatId, optionId, staffId…) belong to the same society.
- **Membership:** one per (user, society). `role = RESIDENT` ⇒ `flatId` and `residentType` required; other roles ⇒ both null. Deactivate (`INACTIVE`), never hard-delete, once a member has history.
- **Amenity booking:** for a slot, `count(CONFIRMED bookings overlapping [startAt, endAt)) < capacity`; check + insert in one serializable transaction. Slot must lie within open/close hours and align to `slotMinutes`.
- **Polls:** one vote per (poll, membership) — DB unique. No voting after `closesAt`. `optionId` must belong to `pollId`.
- **Staff attendance:** at most one open row (`checkOutAt IS NULL`) per staff; gate verify toggles in/out.
- **OTP:** hash with bcrypt, 5-min expiry, max 5 attempts, single-use (`consumedAt`).
